## 已交付

- **配置**（`packages/core/src/config.ts` + `pull-request-policy.ts`）：新增可选
  `review.pull_request.schedule`（仅 `timezone` + `rules`，形状与
  `review.auto_commit.schedule` 相同），global/defaults/instance 三层整体替换解析
  （`resolvePullRequestSchedule`，逐层缓存）。bootstrap 的
  `getExecutionSchedule(workspaceId, targetKind)`：pull_request 事件（含评论命令，
  其 target kind 为 pull_request）优先使用该配置，各层均未设置时回退到解析后的
  `review.auto_commit.schedule`；其余 target kind 始终使用后者。两者都未设置时不做
  时段限制。同步（`asyncTriggers: false`）嵌入模式不延期。
- **持久化延期**（`packages/server/src/deferral-manager.ts` +
  `packages/store/src/review-deferrals.ts`，迁移 `008_review_deferrals`）：有可观测
  store（`storage.database` + `admin`）时，窗口外到达的事件信封按 dedup key
  （triggerName/workspaceId/provider/repoRef/targetKind/branch|url|headSha|baseSha）
  upsert 进 `review_deferrals` 表——同目标新事件替换信封且 `not_before` 不提前——
  并按存储返回的时间武装单定时器；到期原子 claim，经 `resumeHandler` 重新进入常规调度
  （窗口钳制仍然生效，窗口在暂停期间关闭则自然再次延期）。交接成功仅删除仍为 claimed
  的行，交接失败保留重试。最新内存回退优先于旧数据库信封。延期不占用运行中的去重标记。
  启动时把 claimed 行
  重置为 pending 并重新武装全部定时器。窗口内到达的新事件通过 `cancel` 取代同目标
  的待执行延期。无 store 时退化为进程内存定时器，重启即丢失。执行开始后的结果
  （含内存重试链）归 run 生命周期，与既有异步路径同级。
- **评论命令告知**：评论命令（reason 以 `:comment_review` 结尾）被延期时复用 output
  publisher 在 PR/MR 上回复一条说明计划开始时间的评论

## 已知限制

- bootstrap 未创建 store 时延期只存在于进程内存，重启即丢失。延期管理器服务于单进程，
  不提供跨进程租约；执行开始后的重试链仍在内存中，不承诺发布 exactly-once。
- `webhook_events` 持久化保留最近 100 条，跨重启保留，不做长期归档；queued 时间是
  最早可执行时间，不保证队列容量、元数据和前序任务允许届时开始。
