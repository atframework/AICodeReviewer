# M14：多源上下文聚合（context_repositories）

## 状态

已完成（2026-08-28）。稳定合同见 `../architecture.md` §3.2.2，决策见 `../decisions.md` D34。

## 目标

M6 起合同层预留的“显式 selector/alias 才访问辅助仓库”落地：评审经常需要引用主仓库之外的
共享库/契约仓库（内部 SDK、协议定义、公共配置），此前 `aicr.fetch_more_context` 只覆盖主仓库。

## 范围决策（实施前确认）

- VCS 范围：git + p4 + svn 三种辅助仓库一次交付（p4/svn 无真实环境，验收停留在单测合同层）。
- 配置层级：workspace 实例级（`workspaces.instances.<id>.context_repositories`），
  `workspaces.defaults` 可声明默认列表，instance 列表整体替换。
- 暴露方式：浅物化 + 只读挂载进沙箱（agent 用 rg/bat 自由检索），而不是仅 MCP 按需拉取。

## 已交付

- **配置 schema**（`packages/core/src/config.ts` `contextRepositorySchema`）：`alias`
  （path-safe、workspace 内唯一）+ `kind`（git/p4/svn），superRefine 按 kind 强制必填字段
  （git `url`、svn `repository_url`、p4 `depot_path`）并拒绝跨 kind 字段；通用 `max_mb`
  （默认 512）；`workspaces.defaults` 与 `instances` 均接受。
- **物化器**（`packages/vcs/src/context-repos.ts` `materializeContextRepositories`）：
  每次 run 全新物化（wipe + 拉取，不跨 run 缓存）到
  `<workspaces root>/<workspace_id>/context-repos/<alias>`；git `--depth 1` 浅克隆
  （token 走 `http.extraHeader` 不落盘，错误经 `redactGitSecrets` + `scrubText` 脱敏）；
  svn `export --no-auth-cache`；p4 `files -e` + 逐文件 `print -q`（维持不执行
  `p4 sync` 不变式，ssl 端口 best-effort `p4 trust -y`，认证失败 `p4 login` 重试一次）。
  单仓库失败隔离（告警 + `status: failed`），物化后 `max_mb` 强制闸门超限即清理。
  全程经共享 `withTransientIoRetry` 分类器重试瞬时 IO 错误。
- **orchestrator 接线**（`packages/server/src/review-orchestrator.ts`）：确认存在变更文件后
  经 `contextRepositoriesResolver(workspaceId)` 解析并物化；仅 agent 路径（sandbox +
  agentAdapter）生效，直连 LLM 路径跳过；容器沙箱经 `extraMounts` 只读挂载
  `/workspace/context-repos/<alias>`，native 沙箱读 host 路径；task prompt（含压缩重建路径）
  列出可用 alias/kind/revision/路径并约束 problem 仍锚定本次变更文件；
  `ReviewOrchestrationResult.contextRepositories` 记录每 alias 的物化结果。
- **bootstrap 接线**（`packages/server/src/bootstrap.ts`）：`contextRepositoriesResolver`
  从合并后的 workspace 配置解析（缺 workspace 时返回 undefined）。

## 验收

- `config.test.ts`：三 kind 合法配置、缺必填/跨 kind 字段/非法 alias/重复 alias 拒绝、
  defaults 合并与整体替换语义。
- `context-repos.test.ts`（15 用例）：git 浅克隆参数、token 经 GIT_CONFIG env 注入且不进
  argv、clone 重试前重建目录、错误脱敏与失败隔离、svn pin/远端 HEAD 解析、p4 共享
  trust/login/delete 判定（`move/delete` 跳过、`trust -y -f` 回退、session 过期重试）、
  binary 字节保真、文件数上限、并发导出、超帽中止、残留 alias 清扫与失败目录清理。
- `review-orchestrator.test.ts`：物化时机（有变更才物化）、只读挂载、prompt 列出/排除
  失败 alias、结果记录并经 `summarizeReviewOrchestrationForWebhook` 透出、直连路径不物化。
- 文档站校验器扩展：`validate-config-reference.mjs` 的 `enumConceptPaths` 新增
  `workspaces.instances.<id>.context_repositories[].kind`，双语 config-fields 全字段覆盖。

## 已知限制

- v1 每次 run 全新物化，不跨 run 缓存；大型辅助仓库的重复克隆成本后续按需优化。
- git `ref` 支持 branch/tag；SHA pin 未支持（`--branch` 不接受裸 SHA）。
- svn 未提供认证字段（匿名/agent 环境凭据）；p4/svn 物化路径未经真实环境 e2e（见
  `Plan.md` §8.3 Backlog 的 SVN/P4 真实环境项）。
- `workspaces.cache.max_total_gb` 当前无运行时执行，`context-repos` 目录不受其约束；
  运维需按 workspace 数 × `max_mb` 估算卷容量。
