## 审查发现与修复

| 问题 | 修复与验证 |
| --- | --- |
| SVN diff 路径带仓库前缀及 revision 标签，与工作区路径不同；普通修改可能误判为 rename | SVN 专用头规范化，`(nonexistent)` 解析为空侧，用固定 revision 的 `info --xml` 校验并去除 scope 前缀。不同工程同名文件不能通过后缀猜测归属 |
| SVN 复制文件沿 URL 历史回溯到原路径，目录和子文件目标产生重复 patch | 使用显式 base/head 两棵树和最具体的目标路径。真实仓库精确验证修改、复制、新增、删除、scope 初建与批次去重；空过滤结果不扩展为全仓库 diff |
| SVN P7 用例接受错误路径前缀，未运行 review | hook→HTTP→SQLite→resolver→scheduler 后调用真实取文件/diff/审查编排，LLM 与输出为替身；断言各项目精确路径、源码片段、调用次数与独立目录 |
| 发布验收直接调用 core publication 并手动传 snapshot，原文件与 bootstrap 配置不同 | 同一份文件解析产生 bootstrap/config document/digest；真实登录和 changeset API 发布，签名 webhook 自动固定版本；运行中更新 provider/model/channel，旧请求和下一请求分别保持完整旧版/新版 |
| 双实例用例手动刷新 B、顺序请求、共享内存回执 | HTTP 自行采用 head；独立 SQLite 配置/回执连接；屏障控制同时保存，验证同 operation 幂等与不同 operation 冲突；并发重复投递只落一条回执；真实 generation preparer 失败后重试恢复 |
| SQLite busy 用例固定延时持锁，退出监听注册过晚，可能挂起；子进程加载旧 dist | stdin 握手持锁，提前监听退出，超时与 finally 清理；子进程通过 tsx 加载当前源码 |
| 001 迁移 fixture 使用无效实体和占位 hash/snapshot | 使用合法 provider/model group、真实内容哈希与 snapshot ID；升级后验证可重新合并/解析和快照哈希，旧 SQL writer 用事务写入 |
| 测试绕过类型检查，依赖内存实现的私有字段 | 修复 DTO 必填字段、策略调用参数、class 实例替身和公共 `computeStreamId` 用法；对变更测试及其导入执行额外严格 tsc 检查 |

SVN 契约依据为本机 CLI 输出和
[官方 diff 文档](https://svnbook.red-bean.com/en/1.7/svn.ref.svn.c.diff.html)。
原始错误输出和失败回归保存在 `build/logs/p7-svn-*`。
