## 修复清单（全部附单测）

### 高严重级

- **1. 发布 prepare 不校验 workspace match 规则**（`config-publish.ts`）：文件加载路径
   执行 `validateWorkspaceDefinitions`，发布路径只跑图编译——非法 DB workspace 记录
   （RE2 不支持的 matcher、match 引用未知 trigger、source_repo+match 混用、逃逸
   work_path 模板）会 commit 成功后才在 generation build/install 失败
   （`committed_activating`，其他副本 503）。修复：prepare 在图编译后统一调用
   `validateWorkspaceDefinitions(effective)`。测试：四类非法定义均在 prepare 失败
   且 head 不变（`config-publish.test.ts`）。
- **2. v2 路由选中无绑定规则的 workspace 时静默回退首个 workspace**（
   `workspace-runtime.ts` + webhook-common）：route 选中的 workspace 既无 match 规则
   也无 legacy 绑定时解析返回 `unbound`，准入回退首个 workspace，执行期再抛
   `no_route`——事件被错误统计进别的 workspace。修复：v2 分支 `unbound` 直接抛
   `no_route`（与执行路径一致）；legacy 模式保留 unbound→首 workspace 合同。测试：
   `workspace-runtime.test.ts` 双向钉死。

### 中严重级

- **3. 停用 legacy `source_repo` 绑定对整个 trigger 一票否决**（`config-resolution.ts`）：
   停用的 legacy 绑定直接返回 `no_match`，阻断同 trigger 的 match 规则与其他 legacy
   绑定，与 match 路径"跳过停用定义"的语义不一致。修复：停用绑定跳过但仍占有
   trigger——无其他规则时结果为 `no_match`（绝不 `unbound` 回退首 workspace），首个
   启用绑定仍按原顺序胜出。测试：三类组合 + route_denied 组合
   （`config-resolution.test.ts`）。
- **4. restore 的 C12 文件锁比较用 `join(".")`**（`config-publish.ts`）：含 `.`/`/` 的
   map 键（如 provider/model id `openai/gpt-4.1`）编码后与 `formatConfigPath` 不匹配，
   历史 DB 值可绕过当前文件锁恢复。修复：锁路径解析回 token 后结构化前后缀比较。
   测试：带斜杠模型 id 的 restore 拒绝（`config-publish.test.ts`）。
- **5. 路由指向停用 workspace 发布不拒绝**（`config-compiler.ts`）：合同 R03 要求
   "route 指向不存在/停用 workspace → 发布失败"，实现只查存在性。修复：启用规则
   指向 `enabled: false` 的 workspace 抛 `invalid_reference`（停用规则不受影响）。
   测试：双向（`config-compiler.test.ts`）。
- **6. `buildEffectiveConfigView` 硬编码 v1 实体集合**（`config-source.ts`）：v2 合并
   文档的 `routing.rules` 不被识别为实体集合，管理视图把整段路由数组当成一个
   default 叶字段。修复：`MergedConfig` 携带 `formatVersion`，视图按版本取集合。
   测试：v2 route 记录逐字段 provenance（`config-source.test.ts`）。
- **7. 清空可选 number/select 编码出 DTO 非法 set**（`config-ui-runtime.ts`）：renderer
   对空 number 输入回调 `undefined`，globals 编码产出 `{op:"set", path}`（无 value，
   JSON 序列化后服务端必 400）。修复：inherit-or-override 绑定本地抛错（空输入不
   自动变继承，§8.1）；value 绑定按"空=absent"——DB 基线 unset、其他来源无操作。
   测试：三种绑定 × 基线来源（`config-ui-runtime.test.ts`）。
- **8. 双域页错误误归属**（`config-ui-runtime.ts` `apiErrorMatchesField`）：无 entity
   标签的错误只按字段路径后缀匹配，workspaces 页 defaults 错误
   （`workspaces.defaults.review.max_files`）会挂到同形实体字段。修复：实体草稿下
   精确等于本页 globals 字段路径的错误不参与后缀匹配。测试：defaults/实体/标签
   三类归因（`config-ui-runtime.test.ts`）。
- **9. 同页二次暂存静默覆盖首批操作**（dashboard `config-app.js`）：暂存后按原基线
   重新解码，同键 `staged.set` 直接替换——第二轮编辑发布时丢失第一轮操作。修复：
   按操作身份（op+path / op+collection+record）合并，新操作覆盖同身份旧操作。
- **10. PG 连接池无 connect 超时**（`pg-config-store.ts`、`store/src/database.ts`）：`pg`
    默认等 OS TCP 超时，远超仓库 5s 纪律。修复：两池统一
    `connectionTimeoutMillis: 5000`（对齐 CLI migrate）。

## 经核实为非问题（抽样）

- exact matcher 不做 glob 转义但 schema 三形状互斥拒绝；UI matcher 控件
  `{exact,glob}` 同键按畸形处理不编码（双侧防御）。
- `assertSafeWorkPathOutput` 对 `a:b`/`a%25b`/`a\b` 误判为绝对路径——fail-closed，
  编码器不产生此类段。
- UI 并发守卫：所有写操作由 `state.saving`/`state.pending` 单门闩保护，无真实
  绕过路径（`state.saving` 无消费者为刻意深冻结）。
- form-state `entity.id` 命名空间：draft `scope.recordId` 确为 record.id（两侧一致）。
- merge 交换递归预算：assertNoPrototypeKeys 现限 128 层（修复 25 后全路径有界）。
