## 调研依据与设计取舍

审查从 git diff、P4/P5 原始退出条件、schema、发布服务、store、dispatcher、bootstrap、
编排、调度器和现有测试逐层追踪。发现部分既有测试先调用 admission 或只断言对象，
因此增加真实 HTTP、持久恢复和 scheduler.tick 行为验证。

请求作用域使用 [Node.js AsyncLocalStorage](https://nodejs.org/api/async_context.html#asynclocalstoragerunstore-callback-args)
的 run 传播合同。请求体限制核对了已安装 Hono 源码与
[Hono Body Limit 文档](https://hono.dev/docs/middleware/builtin/body-limit)；配置 API
始终统计实际流字节，不依赖 Content-Length 声明。已有不可变快照行不原地修补，
损坏或版本不匹配时拒绝激活；只有缺失行且文件身份一致时可重建。

| 激活失败导致旧实例续租中断，关闭与 GC 竞争 | 心跳独立于激活结果、关闭等待正在执行的 GC 与 generation lease；runtime-config drain 测试 |

取舍：per_commit 提供带提交标记的补丁并维持每事件一次分析；历史改写仍为端点比较。
原生 agent 按 launch 限流，CLI 内部 HTTP 不受网关逐请求控制。预算使用已报告费用，
更新不清空累计金额；费用返回前无法保证远端硬封顶，进程重启不保留内存日预算。
secret 授权约束配置的 env 用途和目的地，部署网络层仍负责 DNS/重定向访问控制。
SQL/Redis 本机合同不等于生产网络、外部平台或付费 LLM 验收。
另核实 `queue.workers.lock_ttl_seconds` 没有消费方，字段清单与双语说明改为预留，
禁止 UI 将其当作可编辑能力；锁过期仍使用 queue backend 自身配置。
