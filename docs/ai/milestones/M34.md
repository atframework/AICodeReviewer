# M34 GitLab 固定版本端到端验收（2026-09-23）

Plan 最后一项收口：固定 `gitlab/gitlab-ce:19.4.0-ce.0` 一次性容器（2 CPU / 6 GiB，
首启 3-10 分钟）上核验 push/MR 筛选→持久入队→`gitlab_problem_issue` 发布的
目标与身份，及窗口外 MR 延期持久化、SIGTERM 重启、下一窗口恢复。
`tests/services/with-gitlab.sh` 负责建容器、PAT 经 runner stdin 注入、一次性开启
`allow_local_requests_from_web_hooks_and_services`、失败导出 webhook 投递日志并
整体清理。

验收期内修复四条真实缺陷/竞态：发布器在 CE 上改用单数 `assignee_id`（复数
`assignee_ids` 是 Premium 功能，静默丢弃）；指派目标必须是项目成员且
`project_authorizations` 异步传播，用例以作者模拟令牌轮询 `read_project` 生效后
再发布；sidekiq 进程内设置缓存把回环 webhook 投递拦成 `URL is blocked` 长达数分钟，
flow 套件在 beforeAll 用裸监听探针消化该窗口，push 腿保留至多一次投递的重发兜底；
MR 腿 webhook 关闭 push 事件，避免夹具分支提交的 push 评审与 MR 评审竞争 assignee。
flow 端到端经 `agent.default: native-llm` 直连回环假 OpenAI 端点，管理员认证用
`username_env`/`password_env` 形式（字面量不生效则 `needsStore=false`，延期静默内存化）。

证据：`gitlab-assignment-live.test.ts` 6 项（三种 issue 模式指派、严重度标签、未知
提交者丢弃、state_event 关闭）与 `gitlab-flow-live.test.ts` 3 项（push 持久入队+发布+
email_mappings 身份；MR 筛选发布+webhook actor 身份；窗口外延期持久化重启恢复）在
全新容器连续两轮全绿（9/9 + 9/9），单测 4466 通过零失败；lint、typecheck、
markdownlint（285 文件）、docs:check、build、eval:validate 通过。`prettier
format:check` 非基线门禁，HEAD 上 templates/builtin 的 .hbs 本就解析失败，未改动。

文档同步：`docs/testing-services.md` GitLab 复现章节与验收命令、`docs/output-channels.md`
指派解析与托管 GitLab issue 节、`docs/site` 中英 outputs/integrations/config-fields/llm/
troubleshooting 五处、示例 config/README、输出 skill 参考及 config-state/build 陷阱条目。
调试容器与临时脚本已清理，验收容器由脚本自动删除。
