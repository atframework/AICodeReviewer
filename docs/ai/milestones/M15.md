# M15：自动提交调度（延迟、执行时段、连续提交合并）

稳定合同见 `../architecture.md` §3.1.1，决策见 `../decisions.md` D35。

## 目标

Git 服务 push、P4 `change-commit`、SVN `post-commit` 自动提交事件统一经过同一套持久
调度合同：先持久接收（202 + `receiptId`），默认延迟 120 秒，在配置的执行时段内按
VCS 历史顺序把提交来源分组键相同的连续提交合并为一个审查批次；替代此前的内存 timer
直启路径（重启丢 pending、每条提交一次分析、无时段控制）。

## 已交付

- **配置**（`packages/core/src/config.ts` `review.auto_commit`，global/defaults/instance
  三层）：`delay_seconds`（默认 120）、多组 `days + windows` 周计划（整体替换、
  `rules: []` 清除限制、默认 UTC、内建 `Intl` 时区与 DST）、`exclude_sources`
  glob/RE2 来源排除（规则内 AND、规则间 OR，re2-wasm 绑定，不退回无界 JS RegExp）。
- **持久调度 store**（`packages/core/src/auto-commit-store.ts` + memory/SQLite/Redis
  三后端）：receipt 原子去重写入（命名空间 + delivery header 或 coverage 哈希）、成员物化、
  stream/workspace 调度头、租约 CAS、原子封存批次 + outbox、元数据失败三态记账
  （`metadata_attempts`/`metadata_next_attempt_at`/`metadata_terminal_error`）、
  分页游标 `metadataCursor`、恢复下限 `resume_not_before`。SQLite 独立 schema
  version（v1→v4 事务迁移已测，含 v3 检查点兼容）；Redis 用 AICR 自有 keys + 有界 Lua，不碰 BullMQ 私有
  keys；memory 非持久性在启动日志显式可见。三后端共享 conformance 场景。
- **调度器**（`packages/server/src/auto-commit-scheduler.ts`）：单去抖 timer 按最早
  到期信号唤醒；扩展（有界 VCS 元数据页 + 来源快照 + 排除判定）→ 连续前缀组批封存 →
  窗口内经 outbox 派发执行；崩溃恢复靠租约过期回收 + `resume_not_before` 下限，
  未封存成员继续处理，已封存成员保留批次归属；执行结果不确定时停止自动重放。
- **VCS 元数据页与连续性**（`packages/vcs/src/contracts.ts`
  `listCommitMetadataPage`）：Git 批量 author/committer、merge/force-push 隔离；
  P4 `changes -m` 分页 + User+Client 最低分组；SVN XML author/revision/copyfrom、
  revprop 可变性快照。sourceSnapshot 带逐字段可用性（known/unavailable/conflicted），
  冲突阻断合并，重投递不新增成员。
- **批次净 diff**：Git 端点 `base..head`；P4 `diff2 <depot>/...@base @head` 两趟
  （枚举趟权威文件集合 + `-u` 趟文本 hunk），add/delete 条目用
  `p4 print -q <path>@<存活端点 CL>` 合成单 hunk（print 次数有界，二进制 NUL 探测
  保持无 hunk 但不丢条目，print 失败明确报错）。
- **入口接线**：`handleReviewOrchestration` 按 provider + 事件名 + targetKind 分类
  （不看 `headSha`），自动提交 await 持久接收后返回 202（`processing.receiptId`，
  `runId` 同值），持久化失败返回可重试 503；PR/评论/issue/手工路径不变。自动路径
  绕开 latest-pending deduplicator；旧内存 timer 路径已废除。bootstrap/CLI serve 组装
  默认 consumer + scheduler；receipt 查询走管理端鉴权。
- **输出与可观测**：一个批次一份结果，多 receipt 关联；失败不关闭旧问题
  （`skipReconcile`）；固定 runId、完整成员范围与执行检查点。完成检查点可恢复本地结果记账，
  `started`/`publication_pending` 检查点要求人工核查，不能自动重放非幂等 publisher。

## 已知限制

- SVN 本地 `file://` 和后续本机 svnserve/hook 均已通过，新增证据见
  `local-priority-queue.md`；目标部署的账户、ACL、HTTP(S) 与认证验收见 `Plan.md` §3。
- memory 后端不持久：进程重启丢失未终结 receipt/成员，仅用于开发/测试。
- 首版批次最多 50 个逻辑提交（内部有界常量，未公开调优字段）。
- 外部发布和本地检查点不是同一事务。执行/发布结果不确定时以 `execution_outcome_unknown`
  终结，dead 批次占住 stream，需人工核查。逐目标回执、对账恢复和端到端 exactly-once 未实现。
- 强推范围与已消费/排除成员相交，或重写事件超过 50 个成员时，以 `exclusion_scope_conflict`
  失败，避免对部分重写成员生成包含范围外变更的净 diff。
- 同一 revision 的 `svn:author` 事后修改只在未封存成员上标 conflicted；已封存批次
  只追加诊断，不重新组批。
