| 发现 | 修复与回归证据 |

| 最新提交包含无类型、无调用方的自动批次发布恢复片段，根 typecheck 报 37 错误，SQLite schema 重复字段 | 去掉 memory/sqlite auto-commit store 中孤立片段及 bootstrap 中引用缺失能力的测试，恢复已交付合同；保留 M23 的 SQLite PRAGMA 失败关闭连接修复。逐目标发布恢复继续属于 Plan 的独立 P1 需求 |
| 数据库校验将任意高 format 当成 v2 | 统一数据库窗口 1–2，拒绝非法整数及未知高版本；原始文件版本仍为 1。`config-version-window.test.ts` 先红后绿，覆盖读取、有效配置解析和发布准备 |
| MigrationRunner 未表示最低 reader/writer 协议与事务模式 | 添加协议 metadata 和状态诊断；缺列账本按 1/1/atomic 读取，apply 在事务中补列而不改旧 SQL checksum；不足协议、篡改账本和非 atomic 模式均拒绝。`migration-runner.test.ts` 覆盖只读旧账本、升级保存和回滚 |
| PostgreSQL 迁移锁可无限等待 | schema 初始化锁等待 5 秒；迁移事务锁等待 5 秒、语句 30 秒。实际旧进程持锁时明确失败，旧进程退出后可重试 |
| CLI 没有正常退出流程，runtime 只计已启动 lease，漏掉已接收定时任务、pending claim 和最终记账 | SIGTERM/SIGINT 停入口与 claim，等待 HTTP、队列、自动批次、lease、后台任务与结果写入；持久延期停止唤醒但允许已接收任务写入，排空后关闭存储和 BullMQ 两个连接。worker 30 秒未排空明确失败，不能报 drained |
| Linux rootless PG fixture 默认尝试不存在的系统 socket 目录 | 专用 PG 子进程明确禁用 Unix socket，仅监听测试 TCP 地址；不修改宿主系统目录或服务 |
| 进程测试硬编码本机 Hyper-V 排除范围，把当前可用端口也排除，反复申请 port 0 后报无空闲端口 | 两处共用显式候选端口绑定与有界冲突重试；不保留机器专属范围，也不无限循环。消费者仍等待实际服务 readiness，不能把端口探测当成预留 |

排空回归包括 `queue-worker.test.ts` 的 pending dequeue/超时、
`runtime-config.test.ts` 的已接收定时任务、`redis-queue.test.ts` 的活跃任务与关闭幂等、
`server-shutdown.test.ts` 的 HTTP 排空及失败状态、`deferral-drain.test.ts` 的持久化后

## 真实版本对与兼容范围

历史代码取自 `c5d221c5fc54bf5322f9eaa4c900937ddc267bd1`，十个模块原样打包，
manifest 保存原始源码和产物 SHA-256。说明与复现边界见
[fixture 文档](../../../packages/core/test/fixtures/migration-versions.md)。历史应用模块
使用当前锁文件中的驱动；没有宣称完整旧发行版依赖环境均已验收。

| 合同 | 实测组合 |
| --- | --- |
| M17 首次升级 | SQLite/PG：旧子进程写入、正常退出，新子进程升级并保留数据；旧进程持有实际写锁时新进程有界失败，旧进程提交退出后恢复 |
| M18 reader/writer 窗口 | 当前协议 1/1、数据库格式 1–2；SQL 旧程序重启拒绝新 schema；Redis 新旧进程交替读写 v1/v2，旧 generation CAS 拒绝、重读后 CAS 成功；当前格式 3 写入拒绝且 head 不变 |
| M19/M20 诊断与恢复 | 原有 CLI status/check/apply、verify、checksum/未知高版本和 restore 回归保留；补旧账本只读检查与协议不足拒绝 |
| 服务排空与进程退出 | 真正 CLI 子进程分别使用 SQLite/Redis queue，必须输出 drained 且自然退出 0；Linux 实际发送 SIGTERM，Windows 由测试 IPC 进入同一信号处理器，未把强制 kill 算作成功 |

首次跨协议升级仍要求运维停止并确认**全部**旧实例退出，然后备份、迁移。数据库锁
不能发现或阻止不认识协议的闲置旧程序；Redis CAS 也不等于任意旧版本隔离。
其他旧提交、线上依赖版本及部署服务仍须独立验收。稳定合同已进入
[架构](../architecture.md) §3.14/§3.16 和 [D46](../decisions.md)。

实现前核验的官方依据：[SQLite 写事务](https://www.sqlite.org/lang_transaction.html)、
[PostgreSQL advisory lock](https://www.postgresql.org/docs/current/explicit-locking.html)、
[Node 信号事件](https://nodejs.org/api/process.html#signal-events)、
[Redis Lua 原子执行](https://redis.io/docs/latest/develop/programmability/eval-intro/)、
[Node 端口绑定](https://nodejs.org/api/net.html#serverlistenport-host-backlog-callback)。
排空顺序与支持版本窗口是本项目的设计选择。
