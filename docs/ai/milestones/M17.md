## 目标

Workspace 动态配置路线图的 P2 阶段:backend 中立的 ConfigStore 合同、
SQLite/PostgreSQL/Redis 三后端、checksummed namespace 迁移账本、
`aicr migrate` CLI、管理 session 持久化,以及业务 StoreDb 的 PostgreSQL
后端接入(消除非 SQLite 启动拒绝)。

## 已交付

- **ConfigStore 合同**(`packages/core/src/config-store.ts`):CAS head
  (`baseRevision` + `operationId` 幂等,同 ID 不同内容拒绝)、不可变
  revision 文档、原子 audit、snapshot pin/refcount、workspace binding、
  admin session(hash+TTL)。实现:memory、SQLite(`sqlite-config-store.ts`)、
  Redis(`redis-config-store.ts`,单 hash-tag 槽位 + Lua 先校验后提交 +
  代际 fencing)、PostgreSQL(`pg-config-store.ts`,advisory xact 锁串行化
  同 namespace 提交)。选择器 `config-store-factory.ts` 由
  `storage.database` 统一决定。
- **MigrationRunner**(`packages/core/src/migration-runner.ts`):namespace
  账本 `schema_migrations`(id/checksum/from/to/appVersion/appliedAt);
  checksum 漂移与未知高版本永远拒绝写入(M16),不自动修复。SQLite 走
  immediate 事务 + busy 有界恢复;PG 复用同一 runner(会话 advisory 锁包住
  CREATE SCHEMA)。业务 sqlite store 保留 legacy `_migrations`,001–006
  DDL 文本冻结 append-only。
- **启动迁移模式与 CLI**:`storage.database.migrate` = `auto`(默认,应用
  待执行步骤)/`verify`(只校验,落后/漂移拒绝启动)/`off`(跳过)。
  `aicr migrate --status|--check|--apply` 与启动共用同一 runner;
  status/check 严格只读(不建文件不建账本表,缺文件按全待执行报告),
  退出码 0/1/2 = 干净/待执行/不安全(M19)。
- **业务 StoreDb 双后端**(`packages/store`):`StoreDb = SqliteStoreDb |
  PgStoreDb` 判别联合;stats/retention/reflection/catalog/recording/
  deferrals/webhook-events 全部双后端实现(pg 分支 `*.pg.ts` 镜像,
  epoch-ms bigint customType);bootstrap 六处消费点全部 await 化;
  `storage.database.kind: postgres` 经 `postgres.url_env` 接入。
- **管理 session 持久化**(`packages/server/src/admin-auth.ts`):token 只存
  哈希 + TTL,经 ConfigStore session 合同落到任一后端;跨副本登出生效;
  bootstrap 结果暴露 `sessionStore`,测试清理路径关闭第二句柄。
- **format converters**:历史 alias/array 迁移幂等、冲突失败、原文只读(M14)。

- dev Redis 为共享实例:残留键会放大 SCAN 型 live 测试往返并超时,验收前
  需 FLUSHDB(已写入 repository-baseline 与 pitfalls)。
- M08 低权限用例要求测试角色具备 CREATE ROLE;CI 非特权 PG 账号需探测
  降级(PostgresStoreSlice 记录)。
- pg catalog 聚合一致性经镜像断言覆盖,非逐调用点 parity(同前)。
- P3–P6 未接线期间,YAML 文件仍是唯一被消费的配置来源;数据库中的
  revision 不影响运行时行为。
