# M41 提示词与工具链现代化、依赖升级、tgrep 索引

## 问题

- 默认评审提示词需要对照最新主流 agent CLI（Claude Code / Codex / Gemini CLI）
  的结构化最佳实践复核，并把代码搜索从"逐文件扫描"升级为索引优先。
- 依赖、镜像 pinned 工具与外部 Agent CLI 需要一轮有证据的升级核验。
- 大仓库评审缺少持久搜索索引：per-run 稀疏物化只含变更文件且运行后删除，
  agent 每次都要重新扫描。

## 方案

- 提示词只做针对性更新（搜索工具约定），保留既有 mission/hard_rules/
  context_strategy/tool_protocol 分层——2026-11 复核确认该分层与
  Claude Code 布局、Codex 默认提示词、Gemini CLI Core Mandates 一致；
  核验记录见 [prompt-research](../../prompt-research.md)。
- 依赖：`pnpm update -r` 全量升级 semver 范围内依赖（astro/hono/yaml/
  @larksuiteoapi/node-sdk/@modelcontextprotocol/sdk/drizzle-orm/pino/sharp 等），
  另手动对齐 undici 8.12.4、@slack/socket-mode 3.1.1、@opentelemetry 0.301.0。
  不升级 zod 4 / typescript 7 大版本（需独立迁移任务）。GitHub Actions 实测
  已全部为最新大版本，未改动。
- 镜像：kubectl 源 v1.36→v1.37（与 dl.k8s.io stable v1.37.2 对齐）；
  yq v4.54.3、dust v1.2.7、xh v0.26.3、doggo v1.4.2、jaq v3.1.2、
  difftastic 0.72.0、ouch 0.8.3、watchexec v2.8.0；新增 tgrep v1.2.7。
  所有 bump 均先核验上游 release asset 命名。外部 Agent CLI（kilo/omp/bun）
  维持 unpinned 每次构建装最新；本轮核验 @kilocode/cli 7.8.27、
  @oh-my-pi/pi-coding-agent 18.18.3、bun 1.4.4。
- tgrep 集成采用"镜像内置 + 服务端索引管理 + prompt/工具引导"，不接上游
  install-agent.sh（仅 Codex/pi 受益且需 Python）。每 workspace 持久缓存
  `<instanceRoot>/.tgrep-cache/`（完整 head checkout + 索引 + meta），
  head 变化或 TTL（默认 24h）触发重建，7 天未用清理；容器沙箱只读挂载
  `/workspace/tgrep-cache`。新工具 `aicr.search_code` 统一外部 agent（MCP 同步）
  与 native-llm（宿主执行 + follow-up 回灌）的搜索行为；一切失败降级为 rg，
  不中断评审。稳定约定见[架构 §3.17](../architecture.md)。

## 验收边界

- 后续复核修正了 Git clone 路径、并发快照、容器索引路径及 JSON 工具识别。
  当前搜索约定见[架构 §3.17](../architecture.md#317-tgrep-代码搜索缓存)，
  真实 Agent 和容器验收范围见[路线图](../index.md#路线图搜索索引与工具链维护m41-之后)。
- 本地：typecheck、全量 vitest、lint、markdownlint、build、eval:validate 通过；
  索引生命周期用 mock 进程做单元测试（真实 tgrep 二进制行为未在本机验证）。
- 真实 agent 端到端（Kilo 生产签收）、容器沙箱内索引挂载与搜索、公网镜像重建
  属于部署验收，需在实际环境执行；本地通过不代表这些路径已验收。
- 公网 cmake-toolset workspace 报告语言切换为 en_US 属独立配置发布，见
  development/README.md 记录。
