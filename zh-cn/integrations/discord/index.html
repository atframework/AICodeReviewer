Discord

AICR 支持 discord_bot，每次发布一条聚合报告，通过 HTTP 接收 help、chat-id、review、status 四种命令。 按钮和自然语言请求未纳入此实现。

创建和安装

Section titled “创建和安装”
  1. 打开 Discord Developer Portal，选择 New Application。
  2. 在 General Information 复制 Application ID 和 Public Key；在 Bot 页取得 Bot token， 通过部署环境注入 AICR_DISCORD_TOKEN。Public Key 用于验签，不能用 Bot token 替代。
  3. 在 Installation 中启用 Guild Install，设置下面的 scopes 和频道权限，使用安装链接添加到目标服务器。
  4. 在 Discord 客户端 User Settings → Advanced → Developer Mode 开启开发者模式。 右键服务器、频道和用户，分别复制 Server ID、Channel ID、User ID。

依据：Discord 官方应用安装教程。

AICR 字段 平台字段
application_id Application ID
guild_id Server ID
callback.public_key Public Key，64 位十六进制字符
会话及报告的 channel_id Channel ID
精确授权的 actor ID 人的 User ID

ID 一律保留为带引号的字符串；下方合成 public key 必须替换为 Portal 中的实际值。

用 bot 和 applications.commands scopes 安装到指定 guild。在命令/报告频道授予 View Channel 和 Send Messages。 此接入使用 HTTP interactions 和 Bot 消息 API；发送和命令不需要 Administrator 或 Message Content，API 成员目录另需 Server Members Intent。 仅支持配置 guild 的普通文字频道（type 0）；DM、论坛帖子、线程、公告频道和 Gateway 接收未实现。 依据：应用命令、频道类型。

发送报告

Section titled “发送报告”

从 example/discord-bot.yaml 开始， 替换所有合成 ID 并设置 token 环境变量。output 引用 im.connections.bot 和准确目的地， ws.outputs.summary: [report] 选择报告渠道。实际审查前合并已有 VCS/LLM 配置。 file-only 可以发送报告；干净结果默认使用 publish_if_summary，覆盖方式见输出策略。

模板仍按 named、workspace、内置的正常优先级选择。总预算为 1900 个 UTF-16 单位， 包含截断提示及可用的安全报告链接。Discord 只允许宿主解析出的作者提醒。

同次审查还通过 issue 渠道发布完整报告时，AICR 先发送 issue，再使用其已确认链接发送简要通知：标题、问题数、严重级别/分类/位置和详情链接，并保留作者提醒。分析、建议和代码留在 issue。没有可用的已确认链接（包括 issue 写入失败）时，渠道仍发送完整报告。此行为不依赖渠道配置顺序，也不需要新增渠道选项。

报告按 Review target、Summary、Problems 分节，问题标题保持单行。 CRLF 与正文多余空行会归一化；内部审查标记不显示，代码围栏、语言提示和正文保留。 自定义模板仍按上述优先级生效；消息达到总预算时显示截断提示。 平台语法见 Discord 消息格式。

启用命令

Section titled “启用命令”

按仓库选择报告时，旧路由可用 outputs.routes.rules[].match.repo_ref 与 trigger、target_kind 取交集。 仓库引用精确匹配并区分大小写；把这些规则放在宽泛规则之前，追加 Bot 输出时保留原有渠道列表。 匹配的旧路由优先于 workspace 输出列表。字段见配置参考。

合并下面片段，保留连接身份和 token，替换 actor、会话、仓库与public key。 review 需要持久 SQLite/PostgreSQL store、数据库配置来源、snapshot 和运行中的 worker； file-only 在创建请求前拒绝 review。平台 callback 无需管理员会话，管理 API 保留原认证。

连接、actor 策略、会话和仓库映射的交集决定权限。 允许配置 guild 文字频道内的用户触发命令时，设置 actors: [{kind: conversation_users}]，无需逐个维护用户 ID。 该策略使用平台认证的 interaction 发送人和频道上下文，不查询成员目录；新增成员无需改配置，离开 guild 不自动取消已接受请求。 私聊不能使用此策略；仍拒绝 any、目录 scope、通配仓库和额外命令。 expires_at 仍生效；重叠 binding 须合并，status 仍只允许原操作人查询原请求。

先部署并激活包含 public key 的 AICR 配置，再把 application 的 General Information → Interactions Endpoint URL 设为公网 HTTPS 地址加 server.path_prefix（若有）和 /callbacks/im/bot。 保存时 Discord 会发送 PING；服务先验证 Ed25519 签名，再响应 PING。 然后注册一个 guild aicr CHAT_INPUT 命令，只包含必填 STRING 参数 command：

工具读取命令清单，只创建或 PATCH 本 guild 的 aicr CHAT_INPUT，不批量覆盖其他命令。 初始回复为 ephemeral（flags 64），满足平台三秒期限；终态使用 Bot API，不依赖十五分钟 interaction token。 依据：interaction 生命周期。

验证流程

Section titled “验证流程”
  1. 在配置的用户和会话中执行 /aicr command: help、/aicr command: chat-id。
  2. 用合成仓库中的真实固定提交执行 /aicr command: review demo 0123456789abcdef0123456789abcdef01234567。 Git revision 为 7–64 位十六进制，配置的 P4/SVN 使用固定正整数。
  3. 保存 request ID，执行 /aicr command: status <request-id>。
  4. 核对完整报告只发到配置的输出目的地；来源会话只收 ID、状态和查询说明。 status 保持同 actor、连接、会话和当前允许的仓库。

ACK 只代表接收，不代表完成分析。后台 readiness 核对平台身份及已配置目的地元数据，缓存 300 秒； 不可用时拒绝接收。本地接收预算为一秒，callback 不等待 VCS、模型、readiness 网络请求或消息发送。 后台在过期前刷新；刷新期间保留原有效期限，成功才续期，失败立即停用目的地。验证命令回复时须跨越缓存刷新周期。

运维与排障

Section titled “运维与排障”

命令没有回复时，在配置的文字频道键入 /aicr，从斜杠菜单选择正确的应用， 在 command 输入框填 help 后发送。指南中的 command: 表示参数栏，不能作为普通聊天文本发送。 初始回复仅操作者可见。若没有命令菜单，检查 guild 命令注册、应用安装及操作者的应用命令权限； 若客户端提示应用没有响应，记录原始错误和命令时间，再核对 Interactions Endpoint URL、回调 HTTP 状态及验签/readiness。

成功接收的合法命令会留下 im_inbox 记录；没有记录也可能是接收前拒绝，不能据此断定没有请求。 help、chat-id 直接使用 HTTP interaction 响应，不经过 Bot 消息 outbox。 Bot 的 Send Messages 用于报告和终态通知，应结合出站失败证据检查。 日志只保留必要元数据，禁止记录 interaction token、签名或完整请求体。 依据：应用命令、 初始响应。

PING/命令 401 时核对 public key 和时间戳头；AICR 本地要求五分钟内的新请求。出站 403 应检查 Bot 的频道权限。429 的 retry_after 单位是秒，回复 outbox 持久保存到期时间。不要把 interaction token 当作 Bot token。其他 guild 或非普通文字频道会在发送前被 readiness 拒绝。

出站超时时，从运行中的 Node 容器核验平台 API 访问。若部署使用代理，按 运行时 HTTP 代理配置核验；宿主请求成功不能代替 readiness。

每次新的 VCS、分析和远端发布前复查当前权限，执行内容继续使用接收时的 snapshot。 停用 binding、connection 或 callback 可停止新的授权工作。通过正常配置发布流程轮换秘密，保持平台身份稳定。 改变 app/guild/Bot 身份后，旧通知不会转发给同名新连接。

完整且目的地匹配的回执才是 delivered；明确失败是 rejected。 进入 POST 后，仅明确的 429 允许到期重试回复。丢失响应、服务端失败和过期 sending lease 保留为 unknown，不会自动重发。 先查远端消息与 journal/outbox，再决定是否创建新请求。

进入 POST 前的本地配置、凭据或存储异常按持久 due time 退避。这些安全重试与明确限流重试共用最多五次的预算，耗尽时为 failed。可能已经发送或回执落库失败时保留 sending 围栏，租约到期后为 unknown。日志只保留固定错误码，不记录上游原始错误。

回滚前停用 ingress 并排空 worker，再更换程序或恢复兼容备份。迁移 013 新增版本化 reply payload 列； 不要删除请求、journal/outbox 来清除 unknown。注销平台资源前核对当前归属，只处理本部署拥有的资源。

仓库测试使用 HTTP 替身和真实本地存储；真实平台需单独凭据并独立验收。 本地通过不代表客户端呈现或公网回调已验证。

提醒审查作者

Section titled “提醒审查作者”

在输出渠道配置显式映射或 API 目录：

API 目录分页读取 guild 成员，匹配 username、global name 和 guild nickname，无法读取用户邮箱。在 Developer Portal 的 Bot → Privileged Gateway Intents → Server Members Intent 开启成员权限；达到 Discord 要求时还须获批。该 REST 接口要求 GUILD_MEMBERS，与命令是否使用 HTTP 无关。仅使用显式映射无需成员列表 intent。出站 allowed_mentions.users 只允许解析出的作者，角色、everyone 和回复提醒保持关闭。匹配 guild 成员不代表该用户能查看私有目标频道。依据：List Guild Members、allowed mentions。

配置目录或映射后默认启用作者提醒；mention_author: false 关闭全部身份解析。映射键可匹配审查作者的邮箱、username、display name 或 P4 提交 workspace；先应用全局邮箱黑名单。使用 API 目录时，映射值必须是候选成员 ID；没有目录时是显式平台 ID；文件目录使用本地成员 key。guess_author 默认 false，保留精确匹配；设为 true 才启用 workspace 关联和专用身份模型。歧义、目录不可用或未匹配时照常发报告并省略 @。拒绝 mention_fallback: all；主评审提示词不接收目录。
